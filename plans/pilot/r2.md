# r2 — Synology LDAP 실물 스키마와 Dex LDAP 연합 토큰 (distribution P0-1, pilot Q2 (c))

> 이름 변경 메모(2026-10-07): 이 기록의 `skills-readers`는 당시 이름이다. 사용자 결정으로 읽기 그룹은 `harness-readers`가 됐다(DESIGN §11).

## 질문

- P0-1: NAS LDAP Server(구 Directory Server)의 사용자·그룹 항목 실물 — 그룹의 멤버 속성이 `member`(DN)인가 `memberUid`인가, 사용자에 `memberOf`가 있는가.
- Q2(c): LDAP 그룹이 Dex 토큰의 `groups` 클레임에 평탄하게 실리는가.
- 덤: LDAPS(636)의 가용성과 인증서, 이 맥의 컨테이너에서 NAS가 닿는가.

## 방법

```sh
# 스키마(읽기만). 바인드 DN·비밀번호는 ~/workspace/dp-charts/argocd/values-override.yaml의 것(출력하지 않았다)
ldapsearch -x -LLL -H ldap://192.168.3.95:389 -D 'uid=admin,cn=users,dc=gyojunan,dc=synology,dc=me' -w "$BINDPW" \
  -b 'cn=groups,dc=gyojunan,dc=synology,dc=me' '(objectClass=posixGroup)' cn objectClass member memberUid
ldapsearch ... -b 'cn=users,dc=gyojunan,dc=synology,dc=me' '(uid=admin)' objectClass uid cn mail memberOf
# LDAPS
LDAPTLS_REQCERT=never ldapsearch -x -H ldaps://192.168.3.95:636 ...     # 검증 없이
ldapsearch -x -H ldaps://192.168.3.95:636 ...                           # 검증 함
echo | openssl s_client -connect 192.168.3.95:636 | openssl x509 -noout -subject -issuer -dates
# Dex 연합 토큰: Dex v2.45.1을 소스에서 macOS용으로 빌드(go 1.27.1)해 호스트에서 띄웠다 — 이 맥의 Docker 컨테이너는 LAN에 닿지 않는다(아래)
dex serve <config: examples/synology-ldap/dex/config.yaml과 같은 커넥터, storage sqlite3, issuer http://127.0.0.1:5557/dex>
tools/pilot/dex_grants.py의 Dex·Verifier로 인가 코드 + PKCE 로그인(사용자 admin) → 토큰 클레임(JWKS 서명 검증)
```

## 환경

- 2026-10-07 05:10~05:16 KST. 맥(192.168.1.x, en0)에서 라우터(192.168.1.1) 경유로 NAS 192.168.3.95. Tailscale 꺼짐(필요 없었다).
- Synology LDAP Server 패키지(DSM 7에서 Directory Server의 새 이름; 설계 문서의 "Directory Server"가 이것), 포트 389·636 둘 다 열림. Dex v2.45.1 소스 빌드(`Dex Version: DEV`, go1.27.1 darwin/arm64) — 컨테이너 판과 같은 커밋.
- 사용자 다섯(admin·altera·yoon94·hue·ukidd002), 그룹 일곱(users·Directory Operators·Directory Clients·Directory Consumers·administrators·dev·devops). **`skills-readers`는 없다.**

## 관측 (원문)

사용자 항목(admin):
```
objectClass: top / posixAccount / shadowAccount / person / organizationalPerson / inetOrgPerson / apple-user / sambaSamAccount / sambaIdmapEntry / extensibleObject
uid: admin
cn: admin
memberOf: cn=users,cn=groups,dc=gyojunan,dc=synology,dc=me
memberOf: cn=Directory Operators,cn=groups,dc=gyojunan,dc=synology,dc=me
memberOf: cn=administrators,cn=groups,dc=gyojunan,dc=synology,dc=me
(mail 없음 — admin만. altera·yoon94·hue·ukidd002는 mail이 있다)
```
그룹 항목(users):
```
objectClass: top / posixGroup / extensibleObject / apple-group / sambaGroupMapping / sambaIdmapEntry
cn: users
member: uid=admin,cn=users,dc=gyojunan,dc=synology,dc=me   (사용자 다섯 전부, DN)
memberUid: admin                                          (같은 다섯, uid)
```
→ 그룹은 `posixGroup`이면서 **`member`(DN)와 `memberUid`를 둘 다** 가진다. 사용자 쪽 `memberOf`도 있다.

LDAPS:
- 검증 없이(`LDAPTLS_REQCERT=never`): 바인드·검색 성공.
- 검증 함: `ldap_sasl_bind(SIMPLE): Can't contact LDAP server (-1)`.
- 636이 내는 인증서: `CN=gyojunan.synology.me`, 발급 Let's Encrypt R13, `notBefore 2026-01-12`, **`notAfter 2026-04-12`(만료)**. 같은 NAS의 DSM 웹 5001은 다른 인증서: Let's Encrypt YE1, `notBefore 2026-10-06 19:15`, `notAfter 2027-01-04` — 웹 인증서는 갱신됐다. DSM 화면(제어판 → 보안 → 인증서)은 기본 인증서(2027-01-05, YR1/YE1)가 LDAP Server 서비스에도 **배정되어 있다**고 보인다(사용자 스크린샷). 그런데 636과 389 StartTLS가 내는 것은 1월에 발급된 옛 R13 인증서다 — 곧 **LDAP Server 데몬(slapd)이 갱신된 파일을 아직 다시 읽지 않은 것**이다(마지막 재시작이 4월 이전). 게다가 IP로 접속하면 CN도 맞지 않는다.

Dex 연합(호스트 빌드, LDAPS 636, `insecureSkipVerify: true`):
- 첫 시도(`emailAttr: mail`): `ldap: entry "uid=admin,..." missing following required attribute(s): ["mail"]` → 로그인 500. Dex는 `emailAttr`가 빈 항목을 거부한다.
- `emailAttr: uid`로 재시도: 로그인 303 → 토큰 200, `expires_in 3599`, 리프레시 있음. 액세스 토큰 클레임(JWKS 검증 통과):
  ```
  iss http://127.0.0.1:5557/dex
  sub CjB1aWQ9YWRtaW4sY249dXNlcnMsZGM9Z3lvanVuYW4sZGM9c3lub2xvZ3ksZGM9bWUSBGxkYXA   (= base64(userID=DN, connID=ldap))
  aud claude-code
  email admin   email_verified true   name admin
  groups ["users", "Directory Operators", "administrators"]
  ```
- Dex 로그: `performing ldap search base_dn=cn=groups,... filter=(member=uid=admin,cn=users,...)` → `login successful ... groups:["users","Directory Operators","administrators"]`.
- 잘못된 비밀번호: `invalid password for user` → 로그인 401, 코드 없음.

컨테이너 네트워크: 이 맥의 Docker Desktop(linuxkit 6.6.12) 컨테이너는 인터넷은 되지만 192.168.1.1·192.168.3.95 어느 LAN 주소에도 닿지 않는다(`nc -z` 실패, host 네트워크 모드도 같음). 그래서 dev compose의 Dex는 LDAP에 붙지 못했고(로그인 60초 타임아웃) 호스트 빌드로 쟀다. 운영 호스트(mini, Linux)에는 해당하지 않는다.

재시작 뒤(사용자가 NAS에서 `sudo synopkg restart DirectoryServer`, 2026-10-07 05:2x KST): 636이 `YR1`, `notBefore 2026-10-06 19:15`, `notAfter 2027-01-04`를 낸다 — NAS 안·맥 양쪽 확인. 패키지 ID는 지금도 `DirectoryServer`다(화면 이름만 LDAP Server).
검증을 켠 연결은 여전히 실패한다: IP(192.168.3.95)는 인증서 이름(`gyojunan.synology.me`)과 다르고, 호스트 이름은 공인 DNS가 221.138.232.2(공인 IP)로 풀려 LAN에서 닿지 않는다. 검증을 켜려면 운영 호스트(mini)에서 `gyojunan.synology.me`를 192.168.3.95로 풀어 줘야 한다(/etc/hosts 또는 split DNS).

사용자가 그룹 `harness-readers`와 사용자 `gyojunan`을 만든 뒤(2026-10-07 05:3x KST, 비밀번호는 기록하지 않는다):
```
cn: harness-readers / member: uid=gyojunan,cn=users,... / memberUid: gyojunan
uid: gyojunan / memberOf: cn=harness-readers,... / memberOf: cn=users,...   (mail 없음)
```
호스트 Dex(LDAPS, `emailAttr: uid`)로 `gyojunan` 로그인 → 토큰 200, 클레임: `email gyojunan`, `name gyojunan`, **`groups ["users", "harness-readers"]`**, 서명 검증 통과. `emailAttr: mail`이었다면 admin과 같은 이유(mail 없음)로 거부됐을 것이므로 오버레이를 `uid`로 바꿨다.

## 판정

| 질문 | 판정 | 기준 대조 |
|---|---|---|
| P0-1 그룹 스키마 | **답**: `member`에 DN. D4의 선례(dp-charts argocd `userAttr: dn`/`groupAttr: member`)가 맞다. `memberUid`도 함께 있어 그쪽 매처도 되지만 선례대로 DN을 쓴다 | 원문 그대로 |
| Q2(c) 그룹 평탄화 | **답**: `groups`에 그룹 `cn` 이름이 평탄한 배열로 실린다. 첫 reader `gyojunan`의 토큰: `["users", "harness-readers"]` | 가입자 토큰의 `groups`에 그룹 이름 — 통과. 탈퇴 시 부재는 r1의 정적 사용자 관측과 같은 경로(Dex는 빈 목록을 생략) |
| LDAPS | **답: 된다.** 인증서는 패키지 재시작으로 갱신됐다(위). 검증은 아직 끌 수밖에 없다(`insecureSkipVerify: true`, 오버레이 기본) — IP 접속은 이름 불일치, 호스트 이름은 공인 IP로 풀린다. mini에 `gyojunan.synology.me → 192.168.3.95` 이름 해석을 두고 `LDAP_HOST=gyojunan.synology.me:636`, `LDAP_INSECURE_SKIP_VERIFY=false`로 바꾸면 켤 수 있다(P5 체크리스트) | 평문 389로 되돌릴 이유는 없다 |
| `emailAttr` | **관측**: admin에만 `mail`이 없다. 실사용자 넷은 있다. 오버레이는 `mail`을 유지한다(admin은 레지스트리 사용자가 아니다). `mail`이 없는 사용자를 reader로 쓰려면 DSM에서 메일을 채운다 | — |
| 읽기 그룹 | 사용자 결정으로 이름이 `harness-readers`가 됐고 NAS에 만들어졌다(위). 첫 팀원 `gyojunan` | 체크리스트 7 완료 |
