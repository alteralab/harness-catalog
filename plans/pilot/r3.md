# r3 — 하네스의 첫 접촉: Claude Code (pilot Q3, 우산 §6-11의 전제)

## 질문

- Q3(a)(b)(c): Claude Code가 어느 MCP 개정판을 말하고, 401의 `resource_metadata`를 따라 RFC 9728 문서를 받고, 인가 서버 메타데이터를 어디서 찾고, 클라이언트 등록을 어떻게 하는가.
- §6-11의 전제: PRM의 `scopes_supported`(교차 클라이언트 audience 스코프 포함)를 그대로 요청하는가.

## 방법

```sh
uv run --script tools/pilot/capture_stub.py --port 5560 --log stub.jsonl [--no-dcr] [--oidc-only]   # 인가 서버 자리의 stub: discovery·JWKS·/register·/auth 기록, 토큰 발급 없음
HC__OIDC_ISSUER=http://127.0.0.1:5560 HC__PUBLIC_URL=http://127.0.0.1:8002/mcp … harness-catalog-server serve --port 8002   # 실물 레지스트리
claude mcp add --transport http hc http://127.0.0.1:8002/mcp -s project
claude -p "hc MCP 서버의 list_skills 도구를 호출해서 …" --max-turns 3 --output-format text
```
변형마다 레지스트리 포트·서버 이름을 바꿨다 — Claude Code가 서버 URL별로 인가 서버 정보를 캐시해 같은 URL로는 stub에 다시 오지 않는다(첫 B·C 시도에서 관측).

## 환경

- 2026-10-07 06:0x~06:2x KST. Claude Code 2.1.258(`claude -p`, 비대화형), 레지스트리 = 이 저장소의 server(스코프 결정 반영판), stub = `tools/pilot/capture_stub.py`.
- 비대화형이라 브라우저 로그인은 일어나지 않는다. 잰 것은 "로그인 직전까지 무엇을 보내는가".

## 관측 (원문; 레지스트리 쪽은 uvicorn 로그)

레지스트리(세 변형 공통): `POST /mcp` → 401, `GET /.well-known/oauth-protected-resource/mcp` → 200, 다시 `POST /mcp` → 401. (RFC 9728 발견 경로를 탄다.)

A. stub이 `registration_endpoint`를 광고(DCR 제공):
  - `GET /.well-known/oauth-authorization-server`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  - `POST /register`  본문: {"client_name":"Claude Code (hc)","redirect_uris":["http://localhost:3118/callback"],"grant_types":["authorization_code","refresh_token"],"response_types":["code"],"token_endpoint_auth_method":"none","application_type":"native","scope":"openid groups audience:server:client_id:http://127.0.0.1:8002/mcp"} (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: -`)
  - `POST /register`  본문: {"client_name":"Claude Code (hc)","redirect_uris":["http://localhost:3118/callback"],"grant_types":["authorization_code","refresh_token"],"response_types":["code"],"token_endpoint_auth_method":"none","application_type":"native","scope":"openid groups audience:server:client_id:http://127.0.0.1:8002/mcp"} (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: -`)
  → `/register` 거절(400) 뒤 `/auth`에는 오지 않았다. Claude 출력: "Dynamic Client Registration rejected (HTTP 400) … 사전 등록된 client_id 등 인증 설정을 수정".

B. `--no-dcr`(등록 엔드포인트 없음):
  - `GET /.well-known/oauth-authorization-server`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  → 메타데이터만 받고 멈춤. Claude 출력: "인증 서버가 동적 클라이언트 등록(DCR)을 지원하지 않는다 … `.mcp.json`에 사전 발급된 클라이언트 ID 같은 인증 정보가 없다".

C. `--no-dcr --oidc-only`(Dex처럼 `/.well-known/openid-configuration`만):
  - `GET /.well-known/oauth-authorization-server`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  - `GET /.well-known/openid-configuration`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  - `GET /.well-known/oauth-authorization-server`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  - `GET /.well-known/openid-configuration`   (UA `claude-code/2.1.258 (sdk-cli)`, `MCP-Protocol-Version: 2025-11-25`)
  → `oauth-authorization-server` 404 뒤 **`openid-configuration`으로 폴백**한다(둘 다 두 번). 그 뒤는 B와 같다.

D. C와 같은 stub + `.mcp.json`의 `oauth: {"clientId": "claude-code"}` (공식 문서: Claude Code는 `.mcp.json`에 `oauth.clientId`·`clientSecret`·`scopes`·`resource`를 받고 CIMD도 지원한다; 사전 등록 ID 관련 버그 보고 #38102·#59460가 있다):
  - `GET /.well-known/oauth-authorization-server`, `GET /.well-known/openid-configuration` (두 번)
  → **동적 등록을 시도하지 않고** "인증이 안 된 상태 — 대화형 세션에서 `/mcp`로 로그인"으로 끝난다. 비대화형이라 `/auth`까지는 가지 않았다. 브라우저 로그인부터는 사람이 대화형으로 확인한다(아래).

## 판정

| 물음 | 판정 |
|---|---|
| Q3(a) 개정판 | `MCP-Protocol-Version: 2025-11-25`(헤더 원문). 2026-07-28 무세션 개정판이 아니다 — SDK가 호환 서빙 |
| Q3(b) RFC 9728 | **답: 따른다.** 401 → PRM → 인가 서버 메타데이터(RFC 8414 경로 먼저, 없으면 OIDC 경로로 폴백) |
| §6-11 전제(스코프) | **답: 그대로 요청한다.** A의 `/register` 본문 `scope`가 PRM의 `scopes_supported`와 글자까지 같다(`openid groups audience:server:client_id:<레지스트리 URL>`) |
| Q3(c) 클라이언트 등록 | **답: 사전 등록 ID는 `.mcp.json`의 `oauth.clientId`로 준다(D에서 DCR 시도 없음).** 등록 안내 한 줄은 "URL 한 줄"이 아니라 "URL + clientId 두 줄"이 된다(우산 V1 "설치 1회"의 정의를 그만큼 넓힌다). 버전 2.1.258 실측; 보고된 버그(#38102)는 재현되지 않았다 |
| OIDC 전용 발견 | **답: 된다.** Dex가 `oauth-authorization-server`를 안 내도 폴백한다 |

## 설계 영향

- §6-11(교차 클라이언트 스코프 광고)은 전제가 성립한다 — 결정 유지.
- 클라이언트 등록: 설계의 "사전 등록 client ID"가 Claude Code에서 성립한다(`oauth.clientId`). 설치 안내는 `claude mcp add --transport http harness-catalog <URL>` 뒤 `.mcp.json`에 `oauth.clientId: claude-code`를 더하는 것으로 적는다(README 템플릿 갱신 필요). Codex는 CIMD·사전 등록 둘 다 지원한다고 문서가 적고(미실측), Cursor는 CIMD 미지원·정적 자격은 문서 불명(미실측).
- 남은 한 걸음: 대화형 세션에서 브라우저 로그인 → 토큰 → 도구 호출. 사용자가 직접 돌린다(비대화형으로는 불가).
